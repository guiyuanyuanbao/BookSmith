# BookSmith 业务流程重构设计

## 走查发现的混乱点

1. **书架与任务的关系不可见**：搜索下载自动入书架，但用户不知道；书架里也看不到某本书"下载了多少章/是否还在下"
2. **失败任务只能去任务页救**：书架上的书显示章节缓存（1021 完成/484 待下载），却没有任何"继续下载"入口
3. **同一本书重复创建任务**：同一本书 8 个任务（多数失败遗留），任务列表成为垃圾场，没有"已有任务在跑"的提示
4. **下载入口有两套对话框**（搜索页/书架页），行为一致但用户感知割裂
5. **搜索下载后强制跳转任务页**：打断用户搜索流

## 重新设计的核心模型

### 数据关系（不变）
```
搜索结果 ──创建──> 任务(bookId) ──写入──> 书架记录(Book) + 章节缓存(Chapter)
                        │
                        └──完成──> 导出文件(Export)
```
**Book 是核心实体**：一个 (bookUrl, origin) 唯一对应一条书架记录；任务只是"一次下载活动"。

### 用户旅程（重构后）

```
┌─ 书源管理 ─┐   ┌─────── 搜索页（主入口）───────┐    ┌─ 书架（资产中心）─┐
│ 导入/同步   │   │ 搜索 → 结果流式 → 比源        │    │ 每本书显示:        │
│ 一键清理    │   │ 选源 → 下载对话框 → 创建任务   │───>│ ① 下载进度条(实时) │
│ 校验/调试   │   │ （提示"已加入书架"，不跳转）    │    │ ② 续传/重跑按钮    │
└────────────┘   └───────────────────────────────┘    │ ③ 目录预览/阅读    │
                                                      │ ④ 再次导出(选格式)  │
                                                      └────────────────────┘
                                                      任务页只负责: 监控/暂停/取消
```

### 任务生命周期（收敛）
```
pending → running(toc) → running(content) → exporting → done
   │           │                 │
   └───────────┴───── paused ◄──┘── (用户暂停/失败自动暂停)
                   │
                   └── resume: 从断点续传（跳过已完成章节）
failed → retry: 只重跑失败章节
canceled（终态）
```

## 实施清单

### 后端
1. `GET /api/books/{id}` 返回该书**活动任务**（running/pending/exporting 状态的最新任务）与章节缓存统计（done/total），前端一次请求即可渲染进度
2. `POST /api/books/{id}/download`：书架直接发起下载（复用已有缓存，若该书已有活动任务则返回该任务 ID——**去重**）
3. 创建任务时若同 (bookUrl, origin) 已有活动任务 → 返回已有任务 ID（`existing: true`），不重复创建

### 前端
1. **搜索页**：下载成功后不跳转，显示"已加入书架，任务 #N 后台进行"+ 侧栏书架入口红点
2. **书架页重构**（资产中心）：
   - 每本书：进度条（done/total 来自活动任务或章节缓存统计）、状态徽标
   - 按钮：继续下载/重跑失败（有活动或失败任务时）、下载导出（无任务时）、目录预览、移除
3. **任务页**：每行加"查看书籍"链接跳书架；同书多任务折叠显示（只显示最新）
4. **书源管理**：清理完成后自动刷新列表
